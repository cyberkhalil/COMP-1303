Formula Sheet

The following formulas may appear on your A4 sheet. All are used in the numerical problems on this exam.

Scheduling Metrics

Turnaround time  = Completion time − Arrival time
Waiting time     = Turnaround time − Burst time
Response time    = First run time − Arrival time
CPU utilisation  = (Total busy time) / (Total elapsed time)
Throughput       = (Number of completed jobs) / (Total elapsed time)

Effective Access Time with Paging

EAT = (1 − p) × memory_access_time
    + p × page_fault_service_time

where p = page fault rate

If a TLB is present:
EAT = hit_ratio × (TLB_time + memory_access_time)
    + miss_ratio × (TLB_time + 2 × memory_access_time)

File System — Inode Capacity (ext4-like, 4 KB blocks, 4-byte pointers)

Pointers per block = 4096 / 4 = 1024

Max file size = (12 direct
              + 1 × 1024 single-indirect
              + 1 × 1024² double-indirect
              + 1 × 1024³ triple-indirect) × 4 KB

Coffman's Four Conditions (mnemonic: M-H-N-C)

M — Mutual exclusion
H — Hold and wait
N — No preemption
C — Circular wait

Belady's Anomaly — FIFO Reference String

Reference string: 1 2 3 4 1 2 5 1 2 3 4 5

FIFO with 3 frames → 9 faults
FIFO with 4 frames → 10 faults  (anomaly!)

Preparation Tips

1. Practice the numericals. The scheduling, Banker's, and page-replacement problems on this exam are the exact kind you have solved in homework. Do them again from scratch — no peeking at previous solutions — until you can solve each in under 10 minutes.
2. Draw your diagrams from memory. The five-state model, the threading models, the RAG, the multi-level page table, and the MLFQ structure. If you can sketch each one on a blank page without reference, you own the concept.
3. Learn the "core problem / solution / trade-off" pattern. Almost every concept in this course fits it. For example: problem = the OS cannot fetch pages fast enough to keep every process running; solution = demand paging with LRU approximation; trade-off = page-fault cost vs. memory pressure.
4. Memorise the key numbers. Memory access ≈ 100 ns; TLB hit ≈ 1 ns; page-table walk ≈ 200–500 ns; page fault from SSD ≈ 50–100 µs; page fault from spinning disk ≈ 5–10 ms. These tell you which side of an optimization actually matters.
5. Prepare the A4 sheet by hand. Write — do not print — the formulas above. The physical act of writing consolidates memory. Include the "unusual" formulas: EAT, inode capacity, Belady's example. When in doubt, include it — the sheet is a safety net, not a cheat.
Common pitfalls to avoid.
  • Confusing turnaround with response time. Read the question twice.
  • Forgetting to increment the serial when declaring a safe sequence — the exam does not care, but a good habit for real life.
  • Mixing up FIFO and LRU in page-replacement traces. FIFO evicts by arrival; LRU evicts by last access.
  • Reporting "safe" for a Banker's state without finding an actual safe sequence. In a written exam, always show the sequence.
  • Skipping the working for a numerical answer. Partial credit is real — method matters.
